# EWP/v3 External KAT Verification

## Purpose

This directory contains an **independent external implementation** of EWP/v3 cryptographic primitives that verifies the Go implementation produces correct output for fixed test vectors.

## Why External Verification?

Internal tests (`v3_crypto_kat_test.go`) can have the same bugs as the implementation. An external oracle written in a different language with different libraries catches:

1. **Misinterpretation of cryptographic specs** (e.g., HKDF Extract vs Expand)
2. **Endianness errors** in domain separation
3. **Length encoding bugs** in AEAD AAD
4. **Transcript binding errors** in key derivation
5. **Nonce construction mistakes**

## Oracle Implementation

**File**: `testdata/v3_kat_oracle.py`  
**Language**: Python 3  
**Dependencies**: `pip install cryptography`  
**Status**: ✅ All vectors verified

### Verified Operations

The oracle independently implements and verifies:

1. **Key Derivation**
   - `v3_credential_prk` - Credential PRK from KAuth + listener context
   - `v3_outer_prk` - Outer PRK for ClientHello encryption
   - `v3_server_hello_prk` - Server hello PRK
   - `v3_handshake_prk` - Handshake PRK for Finished messages
   - `v3_master_prk` - Master PRK for application traffic
   - `v3_expand` - Transcript-bound HKDF expand

2. **Authentication Tags**
   - `v3_route_tag` - O(1) route lookup tag
   - `v3_cookie` - Stateless retry cookie
   - `v3_admission_tag` - Credential admission tag
   - `v3_replay_key` - Replay prevention key

3. **Record Format**
   - `v3_encode_record` - Opaque AEAD record encoding
   - Counter || Type || MetaLen || PayloadLen encrypted

4. **Finished Messages**
   - `v3_finished_verify` - HMAC-based verify data

## Cryptographic Primitives Used

The oracle uses Python `cryptography` library:

- **SHA-256**: `hashlib.sha256`
- **HMAC-SHA-256**: `hmac.new(..., hashlib.sha256)`
- **HKDF-Extract**: `hmac.new(salt, ikm, sha256)` (RFC 5869)
- **HKDF-Expand**: `cryptography.hazmat.primitives.kdf.hkdf.HKDFExpand`
- **ChaCha20-Poly1305**: `cryptography.hazmat.primitives.ciphers.aead.ChaCha20Poly1305`

## Integration with CI/CD

Add to `.github/workflows/test.yml`:

```yaml
- name: Run external KAT oracle
  run: |
    python3 -m pip install cryptography
    cd testdata && python3 v3_kat_oracle.py
```

This ensures every PR and commit is verified against an independent implementation.

## Updating Test Vectors

When adding new cryptographic operations:

1. Add expected output to `v3_vectors.json` (generated by Go KAT test)
2. Implement the operation in `v3_kat_oracle.py` 
3. Add verification test in `verify_kat()`
4. Run both Go and Python tests to ensure agreement

**CRITICAL**: Never copy-paste Go crypto code into Python. The oracle must be an independent implementation based on specs, not a port.
